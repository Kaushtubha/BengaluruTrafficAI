\chapter{Security, Reliability, and Failure Analysis}

\section{Security Architecture and Threat Modeling}
Although BengaluruTrafficAI is a prototype research platform, several defense-in-depth principles have been engineered to prevent common web application vulnerabilities.

\subsection{1. Parameter Length Limits (Buffer Overflow / ReDoS Mitigation)}
In \texttt{backend/app.py} and \texttt{backend/app\_demo.py}, string query parameters undergo length bounds checking:
\begin{lstlisting}[language=Python]
if raw_corridor is not None and len(raw_corridor.strip()) > 32:
    return jsonify({
        "status": "error",
        "message": "Corridor parameter exceeds maximum allowed length of 32 characters."
    }), 400
\end{lstlisting}
This prevents oversized string payloads from consuming memory or precipitating catastrophic backtracking in regex evaluators.

\subsection{2. Coordinate Injection and Numeric Sanitization}
Geographic coordinate parameters (\texttt{lat}, \texttt{lon}) are explicitly stripped, length-checked ($\le 32$ chars), and converted via \texttt{float()}. The system tests for and rejects \texttt{NaN}, \texttt{Inf}, and $- \text{Inf}$, preventing arithmetic poisoning of Haversine distance computations.

\subsection{3. Zero Secret Leakage}
The repository enforces a clean `.gitignore` structure excluding \texttt{.env}, \texttt{.env.*}, \texttt{*.pem}, \texttt{*.key}, and \texttt{*.cert}. No database connection strings, passwords, or deployment API tokens are stored in tracked git objects.
