\section{Non-Functional Requirements (NFR)}
\begin{itemize}[leftmargin=*]
    \item \textbf{NFR-01: Low-Latency REST Response}: API endpoints must return complete JSON payloads in under 150\,ms under local execution, and remain resilient to cloud free-tier spin-up latency (handled via client timeouts of 12,000\,ms).
    \item \textbf{NFR-02: Zero External Cost Infrastructure}: The entire platform must execute indefinitely under a strict \textbf{\pounds 0 / \rupee 0 budget}, eliminating commercial proprietary APIs (e.g., Google Maps, Mapbox, TomTom, OpenAI).
    \item \textbf{NFR-03: Memory Footprint Constraints}: The demonstration backend (\texttt{app\_demo.py}) must operate reliably within a 512\,MB RAM threshold on Render's free tier without trigger-happy Out-of-Memory (OOM) process termination.
    \item \textbf{NFR-04: Graceful Degradation and Fail-Safe Storage}: If the MongoDB logging daemon is offline or unconfigured, the application must catch connection exceptions and revert to structured console logging without interrupting signal control loops.
    \item \textbf{NFR-05: Telemetry Honesty and Disclaimer Consistency}: Heuristic and simulated outputs must carry clear provenance metadata, avoiding deceptive claims of calibrated accuracy.
\end{itemize}

\section{Explicit Out-of-Scope Capabilities}
To prevent scope creep and maintain strict technical boundaries, the following capabilities are explicitly classified as out of scope for this repository version:
\begin{itemize}[leftmargin=*]
    \item Direct electrical hardware actuation of roadside signal controller cabinets (e.g., NEMA TS2 or 2070 controller units).
    \item Automatic License Plate Recognition (ALPR / ANPR) with optical character recognition across non-standardized multi-state license plates.
    \item Real-time turn-by-turn road network routing across alternate municipal bypasses.
\end{itemize}
