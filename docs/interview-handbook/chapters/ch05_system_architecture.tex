\chapter{System Architecture}

\section{Macro Architectural Overview}
BengaluruTrafficAI is architected around a decoupled client-server model separating client-side state presentation from backend telemetry and edge computer-vision processing. The system implements two distinct server operational modes:
\begin{enumerate}
    \item \textbf{Production Cloud Demonstration Architecture}: Deployed on Render and Vercel, serving continuous simulated fluctuations with unified schema contracts.
    \item \textbf{Local Edge Computer-Vision Architecture}: Running locally on developer or edge workstations, integrating live video decoding, deep neural inference, and multi-object tracking.
\end{enumerate}

\section{Failure Boundaries and Recovery Mechanisms}
\begin{itemize}[leftmargin=*]
    \item \textbf{Backend Cold Starts}: Render's free tier idles processes after 15 minutes. The frontend handles this by establishing an extended 12-second Axios timeout, displaying a distinct \texttt{OFFLINE} badge in the header, and continuously attempting background reconnection every 3 seconds.
    \item \textbf{Storage Outages}: Database logging in \texttt{ai/db\_logger.py} wraps PyMongo operations in \texttt{try...except} blocks. If MongoDB is offline, operations fail gracefully to standard console logging without disrupting traffic signal loops.
    \item \textbf{Sensor Data Dropouts}: When camera detection frames drop or vehicle counts evaluate to zero, \texttt{signal\_service.py} falls back to a safe base green allocation of 20.0 seconds per approach, preventing signal freeze.
\end{itemize}
