\chapter{Frontend Architecture: Fundamentals to Advanced}

\section{React Fundamentals Applied in the Application}
The frontend is built using **React 18** functional components, leveraging unidirectional data flow, declarative JSX formatting, and component-level hook lifecycles.

\subsection{State Management with Zustand}
Rather than relying on Redux (which introduces extensive boilerplate actions, reducers, and thunks) or React Context (which triggers re-render cascades across nested components upon single-field updates), state is centralized in a lightweight Zustand store defined in \texttt{frontend/src/store/useStore.js}.

\begin{lstlisting}[language=JavaScript,caption={Zustand Store and Parallel Polling Architecture (\texttt{useStore.js})}]
export const useStore = create((set, get) => ({
  // Core traffic metrics state
  systemStatus: 'ACTIVE',
  trafficData: {
    status: 'online',
    junction: 'Silk Board, Bengaluru',
    active_lane: '--',
    vehicle_counts: { North: 0, South: 0, East: 0, West: 0 },
    total_vehicles: 0,
    tracked_vehicles: 0,
    violations: 0,
  },
  signalData: {
    green_times: { North: 0, South: 0, East: 0, West: 0 },
    priority_lane: '--',
    cycle_time: 0,
  },
  violationsData: {
    total_violations: 0,
    red_light: 0,
    wrong_side: 0,
    speeding: 0,
    no_helmet: 0,
  },
  history: [],

  // Concurrent API polling using Promise.all
  fetchTrafficData: async () => {
    try {
      const [statusRes, signalRes, violationsRes] = await Promise.all([
        api.get('/status'),
        api.get('/signal'),
        api.get('/violations'),
      ]);

      const trafficData = statusRes.data;
      const signalData = signalRes.data;
      const violationsData = violationsRes.data;

      // Update history buffer (FIFO queue, max 20 entries)
      const now = new Date().toLocaleTimeString('en-US', { hour12: false });
      const currentHistory = [...get().history];
      if (currentHistory.length >= 20) {
        currentHistory.shift();
      }
      const validTotal = Number.isFinite(trafficData?.total_vehicles)
        ? trafficData.total_vehicles : 0;
      currentHistory.push({ time: now, vehicles: validTotal });

      set({
        trafficData,
        signalData,
        violationsData,
        systemStatus: 'ACTIVE',
        history: currentHistory,
      });
    } catch (err) {
      console.error('Failed to sync traffic API:', err);
      set({ systemStatus: 'OFFLINE' });
    }
  },
}));
\end{lstlisting}

\subsection{Architectural Significance of \texttt{Promise.all}}
In earlier development versions, \texttt{fetchTrafficData} executed sequential network requests:
\begin{equation}
T_{\text{sequential}} = \text{RTT}_{\text{status}} + \text{RTT}_{\text{signal}} + \text{RTT}_{\text{violations}} \approx 3 \times \text{RTT}
\end{equation}
Over trans-continental or free-tier cloud connections where latency ranges between 200\,ms and 400\,ms, serial polling incurred round-trip delays exceeding 1.2 seconds. Refactoring to \texttt{Promise.all} parallelizes all three HTTP GET requests:
\begin{equation}
T_{\text{concurrent}} = \max\left(\text{RTT}_{\text{status}}, \text{RTT}_{\text{signal}}, \text{RTT}_{\text{violations}}\right) \approx 1 \times \text{RTT}
\end{equation}
This cut telemetry update latency by nearly 66\% and eliminated frame stutter in the dashboard radar.

\section{Component-Level Implementation Details}

\subsection{Operations Dashboard (\texttt{Dashboard.jsx})}
\begin{itemize}[leftmargin=*]
    \item \textbf{Lifecycle Coordination}: Establishes a 3,000\,ms polling interval via \texttt{setInterval} in a \texttt{useEffect} hook, returning a cleanup function to prevent memory leaks when navigating away.
    \item \textbf{SVG Traffic Radar}: An interactive vector radar mapping four Cartesian approach branches, rendering dynamic vehicle counts and pulsating transit dots whose travel velocities scale inversely with traffic congestion.
    \item \textbf{Heuristic Styling Fallbacks}: Evaluates \texttt{trafficData.congestion\_level}. If the backend returns \texttt{UNAVAILABLE}, the component falls back to neutral slate styling (\texttt{text-slate-400}) rather than misrepresenting unavailable data as green low-congestion traffic.
\end{itemize}

\subsection{Traffic Analytics (\texttt{Analytics.jsx})}
\begin{itemize}[leftmargin=*]
    \item \textbf{Safe Load Percentage Bounds}: Calculates lane capacity load as:
    \begin{equation}
    P_{\text{load}}(l) = \min\left(100, \max\left(0, \text{round}\left(\frac{\text{Count}_l}{\max(\text{Total}, \sum \text{Count}_i, 1)} \times 100\right)\right)\right)
    \end{equation}
    This protects against division by zero and clamps percentages strictly to $[0\%, 100\%]$.
    \item \textbf{Emergency Indication}: Integrates a dedicated conditional badge displaying \texttt{EMERGENCY} in rose palette (\texttt{bg-rose-500/20}) if and only if \texttt{signalData.emergency\_override} is active for that lane.
\end{itemize}

\subsection{Driver Assistance Portal (\texttt{DriverPortal.jsx})}
\begin{itemize}[leftmargin=*]
    \item \textbf{Geolocation Error Handling}: Uses the browser's \texttt{navigator.geolocation} API, mapping specific error codes to distinct user feedback:
    \begin{itemize}
        \item Code 1 (\texttt{PERMISSION\_DENIED}): Prompts the user to select an approximate landmark preset.
        \item Code 2 (\texttt{POSITION\_UNAVAILABLE}): Informs the commuter that device satellite lock failed.
        \item Code 3 (\texttt{TIMEOUT}): Handles requests exceeding the 8,000\,ms threshold gracefully.
    \end{itemize}
    \item \textbf{Transparent Queue Disclosures}: Explicitly renders notices stating that clearance delays are unavailable due to camera field-of-view limits.
\end{itemize}
