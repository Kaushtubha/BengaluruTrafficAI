\section{Telemetry Synchronization Cycle}
The application synchronizes data using an event-driven polling loop managed by the Zustand store (\texttt{frontend/src/store/useStore.js}). Figure~\ref{fig:data_flow_diag} traces the lifecycle of an update cycle.

\section{Historical Buffer Management in Memory}
To drive Recharts continuous time-series stream visualizations without overflowing browser memory during long sessions, \texttt{useStore.js} enforces a strict First-In, First-Out (FIFO) sliding window capped at 20 snapshots:
\begin{lstlisting}[language=JavaScript]
const now = new Date().toLocaleTimeString('en-US', { hour12: false });
const currentHistory = [...get().history];
if (currentHistory.length >= 20) {
  currentHistory.shift(); // Evict oldest telemetry point
}
const validTotal = Number.isFinite(trafficData?.total_vehicles)
  ? trafficData.total_vehicles : 0;
currentHistory.push({
  time: now,
  vehicles: validTotal,
});
\end{lstlisting}
This bounds memory consumption to $O(1)$ constant overhead regardless of how many hours the dashboard remains open in an active tab.
